## Annex II — Technical and organisational measures

- **Encryption:** TLS 1.2+ for all data in transit; encryption at rest for databases, backups and file storage provided by our hosting provider.
- **Access control:** access to production limited to named personnel who need it; multi-factor authentication; least-privilege IAM roles; no shared accounts.
- **Authentication:** customer passwords hashed with Argon2id; server-side sessions with `HttpOnly`, `Secure`, `SameSite` cookies; ability to sign out all devices; rate limiting on authentication endpoints.
- **Tenant isolation:** every data access is scoped to the owning account at the application layer; widget delivery reads only published configurations.
- **Data minimisation:** widgets set no cookies, use no fingerprinting, and do not store IP addresses alongside statistics; IP addresses in legal-acceptance records are hashed.
- **Availability and resilience:** managed database with automated backups and point-in-time recovery; infrastructure defined as code; ability to disable individual widgets instantly.
- **Monitoring and logging:** security-relevant events are logged and retained for up to 90 days; alerts on anomalous activity.
- **Vulnerability management:** dependencies monitored and patched; security fixes prioritised.
- **Incident response:** a documented process for detecting, containing, investigating and notifying personal data breaches, as in section 6.
- **Deletion:** account deletion removes customer data from live systems within 30 days and from backups within a further 35 days.
- **Subprocessor management:** written data-protection terms with each subprocessor, reviewed when the subprocessor list changes.
